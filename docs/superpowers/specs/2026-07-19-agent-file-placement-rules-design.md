# Agent 新任务文件放置规则设计

## 目标

增强 `docs/agent/PROJECT_STRUCTURE.md`，让代码 Agent 在创建文件前采用一致的架构判断：

1. 优先复用职责相同的现有文件或目录；
2. 现有位置无法清晰容纳多个紧密关联组件时，才建立功能子文件夹；
3. 测试目录始终镜像源码目录；
4. 无法明确归类时询问用户，不自行创建顶层分类。

本次只调整文件路由规则，不迁移现有代码，也不改变当前包结构。

## 选择的文档位置

规则写入 `docs/agent/PROJECT_STRUCTURE.md`，不新增独立的任务结构文档。

原因：

- 根目录 `AGENTS.md` 已要求 Agent 在定位、创建或移动文件前读取该文档；
- 文件路由、目录创建和测试镜像属于同一职责；
- 避免增加另一份必须同步维护的导航文档；
- `PROJECT_OVERVIEW.md` 继续只保存项目目标和稳定架构背景。

## 核心决策顺序

Agent 在创建正式代码文件前必须按以下顺序判断：

```text
明确新内容的主要职责
  -> 查找职责相同的现有文件
      -> 能保持单一职责：修改现有文件
      -> 无法保持单一职责：继续判断
  -> 查找同一功能的现有子文件夹
      -> 存在：放入该子文件夹
      -> 不存在：继续判断
  -> 选择最接近的领域目录
      -> simulation / vlm / tools
  -> 是否形成独立、可扩展的多文件工作流？
      -> 是：建立功能名子文件夹
      -> 否：在领域目录新增单个模块
  -> 仍无法明确归类：询问用户
```

判断依据是文件职责和依赖关系，不是名称相似、日期接近或当前对话方便。

## 复用现有位置的规则

以下情况默认不新建子文件夹：

- 新逻辑属于某个现有文件已经声明的职责；
- 只增加一个小型模块、通用函数或适配器；
- 只是修复、扩展或测试现有行为；
- 只新增一份测试、文档或配置；
- 新内容可以放入现有目录而不造成职责混杂；
- 任务名称是临时实验名、日期、提交名或对话描述。

查找顺序固定为：

1. 相同功能的现有子文件夹；
2. 相同职责的现有代码文件；
3. 对应领域根目录；
4. 经确认的共同上层；
5. 询问用户。

多个领域都会使用的能力不能复制到各任务目录。只有能够给出稳定、领域无关的职责名时，
才考虑放到共同上层；不能用模糊的 `common.py` 或 `utils.py` 收纳暂时找不到位置的代码。

## 新建功能子文件夹的条件

只有同时满足以下基本条件时，才新建功能子文件夹：

- 新任务预计包含至少两个紧密关联的正式代码文件；
- 这些文件共同构成一个可独立理解和测试的功能或工作流；
- 放在领域根目录会使职责或文件列表明显混乱；
- 子文件夹使用长期稳定的功能名称，而不是阶段序号或临时名称。

以下特征可以进一步支持建立子文件夹：

- 同时包含 runner、policy、screening、schema、trace 等多个组件；
- 有独立 CLI；
- 有独立输入、输出和错误边界；
- 后续大概率继续扩展；
- 可以作为整体运行和验收。

满足“两个文件”不是自动建目录的充分条件。如果两个文件分别属于已有模块职责，仍应放回
对应的现有位置。

## 领域与命名规则

顶层领域保持稳定：

```text
src/vla_project/simulation/
src/vla_project/vlm/
src/vla_project/tools/
```

功能子文件夹位于最接近的领域之下，使用小写蛇形功能名：

```text
src/vla_project/vlm/grounding_smoke/
```

禁止使用以下类型的名称：

```text
stage4/
new_task/
temp/
test_version/
2026_07_19/
```

阶段顺序和时间信息属于 `CURRENT_STATUS.md`、WORKLOG、specs 或 plans，不通过代码目录名
表达。

## 测试镜像

新增源码子文件夹时，测试目录必须保持同样层级：

```text
src/vla_project/vlm/grounding_smoke/targeting.py
-> tests/vlm/grounding_smoke/test_targeting.py
```

如果正式代码放在已有领域目录，测试也放在对应的现有测试领域目录，不为了测试单独创建
新的任务层级。

## 示例

### 复用现有文件

新增 grounding 框解析逻辑：已有 `diagnose_vlm_grounding.py` 承担 grounding prompt、
解析和画框职责，因此直接扩展该文件。

新增相机投影数学函数：已有 `simulation/camera_geometry.py`，因此直接扩展该文件。

### 放入现有领域目录

新增一个独立但单文件的 VLM 统计模块：放入 `src/vla_project/vlm/`，并在 `tests/vlm/`
增加镜像测试，不新建任务文件夹。

### 新建功能子文件夹

新增 grounding smoke 工作流，同时包含 targeting、screening 和 runner：

```text
src/vla_project/vlm/grounding_smoke/
├── __init__.py
├── targeting.py
├── screening.py
└── runner.py

tests/vlm/grounding_smoke/
├── __init__.py
├── test_targeting.py
├── test_screening.py
└── test_runner.py
```

这是功能名明确、包含多个协作组件、拥有独立工作流和测试边界的合理子包。

## Agent 执行要求

创建新文件前，Agent 必须在内部检查并能回答：

1. 是否已有职责相同的文件？
2. 是否已有同一功能的子文件夹？
3. 新内容主要属于哪个领域？
4. 为什么现有文件或目录不能清晰容纳它？
5. 是否确实形成多文件独立工作流？
6. 测试镜像路径是什么？

如果第 4 或第 5 项没有明确答案，默认不新建子文件夹。若领域边界仍不明确，必须先询问
用户。

## 实施范围

本次实施只修改 `docs/agent/PROJECT_STRUCTURE.md`：

- 增加目录创建决策流程；
- 增加复用现有文件和目录的优先级；
- 增加新建功能子文件夹的条件；
- 增加命名、测试镜像和示例；
- 在最后检查中加入创建子文件夹前的判断项。

不修改 `AGENTS.md`，因为它已经要求创建或移动文件前读取 `PROJECT_STRUCTURE.md`；不修改
源码、测试、配置、README 或其他项目知识文档。

## 验收标准

- 文档明确表达“优先复用，必要时才新建子文件夹”；
- 决策规则可以区分扩展现有文件、在领域目录新增模块和建立功能子包三种情况；
- 新建子文件夹不由日期、阶段编号或文件数量单独决定；
- 测试镜像规则与现有项目结构一致；
- 无法归类时要求询问用户；
- 文档没有与现有 `simulation`、`vlm`、`tools` 路由规则冲突；
- 除 `docs/agent/PROJECT_STRUCTURE.md` 外不产生实施变更。
