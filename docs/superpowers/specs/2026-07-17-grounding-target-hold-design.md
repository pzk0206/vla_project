# Grounding 最近可靠目标与最大失效步数设计

## 目标

在 Grounding 世界坐标闭环 smoke test 中，允许红块被机械臂短暂遮挡时继续完成少量安全动作，同时保持运行时真值隔离。系统只能复用此前由 VLM 框、相机反投影和冻结补偿得到的目标世界坐标，不能读取 PyBullet 红块真值来生成动作。

本功能只处理“已经获得过可靠目标，随后短暂不可见”的情况。一开始就不可见、清晰画面下 VLM 返回无效框、API 失败、目标跳变、目标越界和无进展仍按原原因中止，不用历史目标掩盖其他故障。

## 方案比较

### 方案一：不可见立即中止

优点是最保守、实现简单；缺点是现有动态筛选已经证明机械臂靠近时普遍产生遮挡，闭环会在控制能力得到验证前结束。

### 方案二：保存最近一次动作方向

优点是实现成本最低；缺点是机械臂会机械重复旧方向，不能随末端当前位置重新判断 `stop` 或切换主误差轴，容易越过目标。

### 方案三：保存最近一次可靠目标世界坐标

每一步都使用“缓存目标坐标减去当前末端坐标”重新计算动作。它保留了本体反馈和确定性控制，只暂时跳过新的视觉定位，因此是本轮采用的方案。

## 状态和配置

在 `grounding_smoke` 中增加：

```yaml
max_stale_target_steps: 4
```

闭环状态增加：

- `last_valid_target_world`：最近一次通过工作区、跳变和反投影检查的补偿后目标坐标；
- `stale_target_steps`：连续使用缓存目标进行控制的次数；
- `decision_source`：本步为 `fresh_vlm` 或 `held_vlm_target`。

`4` 步对应当前每步 `2cm` 的最多 `8cm` 历史目标控制距离。它小于单个 episode 的10步总预算，并可覆盖从约10cm起点靠近到2cm停止阈值的大部分短时遮挡段。

## 数据流

### 清晰且定位有效

1. 采集图像并调用 VLM；
2. 将红块框中心反投影并应用冻结补偿；
3. 通过既有工作区、目标跳变和无进展检查；
4. 更新 `last_valid_target_world`；
5. 把 `stale_target_steps` 重置为 `0`；
6. 根据当前末端位置计算并执行动作；
7. 日志记录 `decision_source=fresh_vlm`、`target_age_steps=0`。

### 可见率低于 clear 阈值

- 如果尚无 `last_valid_target_world`，保持原行为，以 `visibility_out_of_scope` 中止，不调用 VLM；
- 如果已有缓存且 `stale_target_steps < max_stale_target_steps`，不调用 VLM，把计数加一，使用缓存目标和当前末端位置重新计算动作；
- 如果下一次使用会超过上限，以 `stale_target_limit` 中止，不再执行动作；
- 历史目标步骤保存原图，不伪造 VLM 框或标注图。

### 其他异常

以下情况不回退到缓存目标：

- 清晰画面下 API 调用失败；
- 清晰画面下无有效红块框；
- 新目标反投影失败、越界或相对上一目标跳变超过3cm；
- 连续无进展或 IK 执行失败。

这样可以避免把网络、模型格式、几何和控制问题错误归因于遮挡恢复。

## 策略边界

目标坐标到离散动作的计算抽成可独立测试的纯计算入口。新入口只接收缓存的 VLM 目标、当前末端坐标、安全状态和配置，不接收 `block_pos` 或 `true_block_pos`。

复用缓存目标时：

- 每步重新计算 `dx`、`dy`、预测距离和主误差轴方向；
- 继续执行既有 `stop_distance_xy` 与无进展保护；
- 目标本身不变，因此本步 `target_jump_xy=0`；
- 不重复应用冻结补偿，避免把补偿叠加多次。

## 日志与批次判定

每条 trace 增加：

- `decision_source`；
- `target_age_steps`；
- `used_target_hold`；
- `corrected_target_world`，历史目标步骤写入实际缓存值；
- `api_called`，明确历史目标步骤没有产生付费请求。

episode summary 增加：

- `num_fresh_vlm_steps`；
- `num_held_target_steps`；
- `max_target_age_steps`；
- `recovered_from_occlusion`。

批次不再要求 `all_clear=true`，因为这会与遮挡恢复目标矛盾。通过条件改为：三个固定案例全部成功、每个案例至少有一次 `fresh_vlm`、没有超过陈旧目标上限、API 总调用量不超过原硬上限。可见率仍完整记录，不能删除遮挡步骤。

## 测试与验收

自动测试必须先失败再实现，覆盖：

1. 首帧不可见且无缓存时立即中止；
2. 一次可靠定位后连续不可见，使用同一目标但根据新末端位置重新计算动作；
3. 历史目标步骤不调用 VLM；
4. 第4次历史目标决策允许执行，第5次触发 `stale_target_limit`；
5. 新的可靠定位会更新缓存并把计数重置为0；
6. 清晰画面下 API 或框错误不被缓存掩盖；
7. 动作入口签名不含任何红块真值；
8. trace、episode summary 和批次通过条件能够区分 fresh 与 held；
9. 完整测试套件在 `vla_env` 中通过。

自动测试通过后，先用不调用 VLM 的可注入序列验证状态机，再运行三个固定在线 smoke cases。真实红块坐标继续只存在于事后评分闭包和输出指标中。

## 非目标

本轮不处理长期或永久遮挡，不增加双相机，不主动移动相机搜索目标，不在遮挡期间估计红块运动，也不训练 action token 或 LoRA。若目标可能被外力移动，历史坐标机制必须停止使用，后续另行设计重新观测策略。
