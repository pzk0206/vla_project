# Visual Input Strategy for BC Training — Design

**日期：** 2026-08-06
**状态：** 待实施
**依赖：** [expert_topdown_v1 派生](../plans/2026-07-31-expert-topdown-view-dataset.md)、[可见性审计](../plans/2026-07-27-expert-dataset-visibility-audit.md)、[action tokenization 审计](../plans/2026-07-31-action-tokenization-audit.md)

## 问题

当前有两套冻结的 300-episode 专家数据集，共享完全相同的 state/action 标签，但相机视角不同。行为克隆训练尚未启动。必须选择一种视觉输入策略才能继续。

## 两套数据的关键差异

| 维度 | 斜视 `expert_scaling_v1` | 垂直俯视 `expert_topdown_v1` |
|---|---|---|
| 相机位置 | eye≈`[0.4, -0.2, 1.5]`（左前方斜向下） | eye=`[0.0, 0.4, 3.0]`（正上方垂直向下） |
| 图像分辨率 | 224×224 | 448×448 |
| 总帧数 | 9,894 | 9,894 |
| clear | 9,479（95.81%） | 7,024（70.99%） |
| partial | 411（4.15%） | 477（4.82%） |
| severe | 4（0.04%） | 2,393（24.19%） |
| 含 severe 的 episode | 1/300（episode 105） | 300/300 |
| 首帧 | 300 clear | 300 clear |
| 终止帧 | 245 clear、55 partial | 300 severe |
| 像素→世界映射 | 非线性，需冻结 (+2.492cm, -1.947cm) XY 补偿 | 近似线性，未校准偏差 |
| 独立验证误差 | 15/15 ≤3cm（clear 样本） | 无对应 calibration |
| VLM grounding 证据 | 4/4 框中心关联正确；第二轮 smoke 3/3 task_success | 无 grounding 数据 |

## 斜视的劣势

1. **投影非线性**：2D 像素到 3D 工作平面需要反投影，且存在系统性偏差。这已通过冻结 (+2.492cm, -1.947cm) 的 XY 补偿缓解，在独立 clear 验证集上为 15/15 ≤3cm。但这个补偿只对当前固定相机位置有效——相机一旦移动就需要重新校准。对于训练来说，这层校准已经固化在数据中，策略不需要学习它。

2. **接近目标时的部分遮挡**：55/300 终止帧为 partial（机械臂末端从侧面部分遮挡红块）。这是任务过程的固有部分，不是数据采集缺陷。对于 BC 策略学习来说，终止帧是关键帧——模型需要在这些帧里学会"已到达，停止"。以 partial 可见率做 stop 决策比以 severe（俯视的 300/300）做 stop 决策难度低一个数量级。

3. **透视畸变对策略泛化的隐式负担（推测，无直接实验证据）**：斜视画面中红块随位置不同呈现不同形状和大小。BC 策略可能额外学习透视不变性，而非纯粹的运动策略。如果后续换相机角度，策略泛化能力可能弱于俯视策略。但这个风险在"最小 BC 对照"阶段不致命——我们的目标是验证训练管线可行，不是生产级泛化。

4. **工作空间远端分辨率下降**：远离相机的红块位置，像素覆盖率更低。这可能在 VLM grounding 阶段引入距离相关的精度退化，但对 BC 训练来说，224×224 的 RGB 输入是模型统一处理的，分辨率下降已经编码在像素中。

## 俯视的劣势

1. **终止帧系统性遮挡（致命）**：300/300 终止帧 severe——机械臂从正上方下降时，末端完全遮住红块。BC 策略在最关键的动作终止阶段看到的是被遮挡的红块，或者根本看不到红块。这不能靠"保留全量数据、后续筛选做对照"绕开——完整删除 severe 终止帧会导致 300 条 episode 全部失去终止 transition。

2. **整体严重遮挡率 24.19%**：近四分之一帧 severe。如果过滤 severe 帧训练，会丢失大量接近目标的 transition（恰好是动作最关键的阶段）；如果保留，模型要在 severe 帧上学习有意义的动作映射，这违背了 BC 的基本假设。

3. **无 grounding 标定证据**：俯视从未经过 VLM grounding 或闭环 smoke 验证。我们不知道在这个视角下 VLM 的定位精度是多少、系统偏差多大。斜视有从 Qwen 框中心到世界坐标的完整校准链和独立验证数据，俯视没有。

4. **派生非原生**：俯视图是重放生成的，不是从真实相机采集的。虽然渲染确定性已验证（9,888 exact + 6 tolerance），但渲染管线本身是一个未建模的中间层。如果后续需要修改相机参数或图像尺寸，需要重新跑整个派生流程。

## 三条路径

### 方案 A：斜视单视角主基线（推荐）

只用 `expert_scaling_v1`（224×224 斜视）训练和评估。

- **优点**：数据质量最高（95.81% clear），VLM grounding 证据链完整，smoke 3/3 task_success 已验证相同相机角度下的模块化闭环。
- **缺点**：没有利用俯视派生数据，透视畸变可能导致策略泛化能力弱于俯视；224×224 分辨率低于俯视的 448×448。
- **风险**：低。这是最保守、证据最充分的路径。

### 方案 B：俯视单视角对照

只用 `expert_topdown_v1`（448×448 俯视）训练和评估。

- **优点**：像素→世界映射近似线性，几何关系简单，理论上策略更容易学习和泛化。
- **缺点**：终止帧 300/300 severe，BC 策略在最关键帧没有可见目标；无 VLM grounding 证据；24.19% 帧 severe。
- **风险**：高。当前证据不支持俯视单视角能训练出有用的 BC 策略。

### 方案 C：双视角融合

同时使用两套视角，可能是早期融合（通道拼接）、晚期融合（双编码器）或随机视角增强。

- **优点**：充分利用已有数据，不同视角提供互补信息（斜视首帧好但终止帧 partial，俯视首帧好但终止帧 severe），可能学到更鲁棒的表示。
- **缺点**：工程复杂度显著增加（双数据加载、双编码器或视角对齐），当前训练基础设施为零，双视角训练是第一个实验就上难度。
- **风险**：中。值得作为下一步但不是第一步。

## 建议

**先做 A，再做 C。不做 B。**

1. **第一轮（立即）**：以斜视 `expert_scaling_v1` 为主基线，做 episode 级训练/验证划分，重新拟合 tokenizer 边界，实现连续回归 + 32 箱 absolute_q + 64 箱 delta_q 三个最小 BC 对照组。
2. **第二轮（A 跑通后）**：把俯视 `expert_topdown_v1` 作为对照实验加入——同样的 episode 划分、同样的 tokenizer 边界，只换图片源，直接比较训练/rollout 指标。
3. **第三轮（A 和俯视对照都有结果后）**：如果两个单视角各有优劣，再做双视角融合。如果斜视已经够好，俯视派生作为对照证据即可，不必强制融合。

### 为什么不做 B

不是永远不做俯视单视角——而是**不能拿它当第一个基线**。第一个基线的作用是验证"训练管线 + BC 方法 + tokenizer 在这个任务上能学到东西"。如果拿俯视做第一个实验，一旦失败（终止帧 severe 导致无法学会 stop），我们不知道是训练管线的问题还是数据的问题。斜视数据质量经过多轮验证，用它做第一个基线可以排除数据质量这个变量。

### 为什么 A→C 而不是直接 C

直接双视角需要同时解决数据加载、双编码器架构、视角对齐和训练超参四个新问题。零训练基础设施的前提下，调试这四个问题的组合爆炸不可接受。先跑通单视角，再评估是否需要双视角。

## 对下游的具体影响

| 决策点 | 影响 |
