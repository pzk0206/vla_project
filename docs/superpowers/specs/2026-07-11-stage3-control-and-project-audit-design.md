# Stage 3 方向控制修复与项目审查设计

## 目标

修复 `stage3_probe.py` 中“决策日志记录离散方向，但 heuristic 实际绕过方向直接追踪完整悬停坐标”的控制路径错误，并对当前小型项目做一次证据驱动的整体审查，找出同类的配置、执行、日志或终止语义不一致问题。

## 范围

本次检查覆盖：

- `control_arm.py` 的专家轨迹采集和 episode 摘要逻辑。
- `stage3_probe.py` 的决策、方向映射、动作执行、trace 和终止逻辑。
- `sim_config.yaml` 中配置项是否被代码实际消费，以及命名、单位和阈值语义是否一致。
- `dataset/` 与 `probe_runs/` 现有输出能否支持当前阶段判断。
- `README.md`、`WORKLOG.md` 和 `vla_robotic_study_plan.md` 是否与修复后的真实行为一致。

不在本次范围内：

- 接入或调用真实 VLM API。
- 新增批量评估系统 `evaluate_probe.py`。
- 大规模拆分模块或重构项目架构。
- 改变 Baseline 1 已验证的数据采集参数，除非发现参数没有生效或语义明确错误。

## 推荐方案

采用“小步修复、全链路审查、回归测试”的方式。保留现有两个主脚本，只提取必要的纯逻辑函数，避免为了测试而进行大规模重构。每个确认的行为错误都先通过失败测试复现，再做最小修复。

## 控制路径设计

当前决策链应统一为：

```text
观测和状态
-> heuristic 或 API 决策器
-> direction
-> 世界坐标 delta
-> 下一步 target_pos
-> IK 和 PyBullet 执行
-> 动作后状态与 trace
```

heuristic 和 API 必须共享 `direction -> delta -> target_pos` 路径。除 `stop` 外，任何方向都只能在 x/y 平面移动 `probe.move_step_xy`；z 坐标保持当前 episode 的悬停目标高度。`stop` 不应制造新的横向位移。

方向含义明确限定为 PyBullet 世界坐标：

- `left`: x 减小。
- `right`: x 增大。
- `front`: y 增大。
- `back`: y 减小。
- `stop`: x/y 不变。

该定义不等同于相机图像空间的左右前后。后续 VLM 接入前必须单独完成图像方向到世界坐标动作的校准，本次不实现该校准。

## 审查方法

逐条追踪以下五条数据流：

1. YAML 配置值是否到达实际运行分支，是否存在读取后未使用、硬编码覆盖或单位不一致。
2. 决策器输出是否真实决定下一步目标坐标，是否存在日志与执行分叉。
3. trace 字段是否记录动作前、动作目标和动作后的真实值，字段名是否与含义一致。
4. 成功、stuck、max steps 和异常退出的判定阈值是否一致，是否都能产生可诊断结果。
5. 输出文件的覆盖、追加、目录清理和图片路径是否与文档描述一致，是否会丢失需要复盘的证据。

发现的问题分为两类：

- 明确 bug：可以从代码路径、测试或输出数据证明行为与声明不一致。本次补测试并修复。
- 改进建议：没有导致当前行为错误，或需要扩大架构范围。只记录，不在本次顺手重构。

## 错误处理原则

- 非法方向值必须显式拒绝，不能静默变成不可预测动作。
- API 文本解析失败可继续使用当前的安全 `stop` 兜底，但 trace 必须保留原始响应。
- PyBullet 资源继续通过 `finally` 清理。
- 审查如果遇到缺失依赖或无法运行的环境问题，应明确记录验证边界，不把静态检查表述成运行成功。

## 测试设计

新增轻量 Python 单元测试，优先使用标准库 `unittest`，避免为当前小型项目增加测试依赖。

核心回归测试覆盖：

- 五个方向到世界坐标下一目标的映射。
- heuristic 与 API 来源不会改变方向执行语义。
- `move_step_xy` 确实控制单步 x/y 位移。
- `stop` 不产生横向移动。
- 非法方向明确报错。
- 审查中发现的其他纯逻辑 bug，各自先新增一个能复现问题的测试。

验证层级：

1. `unittest` 纯逻辑测试。
2. 所有 Python 文件的语法编译检查。
3. 当前环境依赖齐全时，以 DIRECT 模式运行一次 heuristic probe，核对 trace 中方向、目标坐标与真实动作一致。
4. 对现有 dataset/probe JSONL 做结构和统计检查。
5. 检查文档阶段描述与验证证据一致。

## 完成标准

- 原控制路径 bug 有先失败、修复后通过的回归测试。
- heuristic 不再绕过离散方向执行路径。
- 审查范围内每条数据流都有检查结论。
- 所有确认的同类小 bug 均有证据、测试和最小修复；其余建议明确留作后续。
- 验证命令和实际结果被完整汇报，不夸大缺失依赖下的运行结论。
- 保留用户当前未提交改动，不覆盖或回退无关内容。
